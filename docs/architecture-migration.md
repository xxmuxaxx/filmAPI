# План перехода на новую архитектуру

Статус: миграция завершена, автоматические и браузерные проверки пройдены. 20 октября проверены публичные страницы, авторизованный профиль и диалог редактирования.

## Решение

Использовать FSD с небольшим количеством срезов и заменить Redux на Zustand + TanStack Query.

- Zustand — небольшое общее клиентское состояние сессии.
- TanStack Query — загрузка и кеширование фильмов, подсказок поиска и текущего пользователя; мутации и обновление кеша.
- URL — применённый поиск, фильтр, страница и размер страницы каталога.
- React и Ant Design Form — ввод, валидация, открытые окна и воспроизведение трейлера.

Не переносить существующие Redux-редьюсеры целиком в Zustand. После разделения ответственности большая часть глобального состояния исчезает.

React Router в declarative mode, Axios, Ant Design, Sass и runtime-конфигурация API сохраняются. Замена маршрутизатора, UI-библиотеки и способа хранения токена не входит в миграцию.

FSD выбрана ради явных направлений зависимостей и владения кодом. Для текущих пяти страниц не нужны обязательные widgets для каждого блока, features для каждого поля, универсальный CRUD-движок или дополнительные слои repositories/services/use-cases. Компонент, используемый только одной страницей, может оставаться внутри этой страницы.

## Что мешает сейчас

1. В core смешаны инфраструктура, компоненты приложения и бизнес-модули; modules содержит другую часть тех же сценариев.
2. HTTP-клиент импортирует store и действия пользователя. Получается зависимость транспорта от приложения и цикл через API-модули.
3. useActions объединяет все действия movie и users, требует уникальности имён и скрывает зависимости компонентов.
4. movieReducer хранит серверные данные, ввод поиска и пагинацию. Часть пагинации уже принадлежит URL.
5. Каталог и фильм вручную синхронизируют Redux с локальными состояниями запроса; разные вызовы разделяют один activeItem.
6. Профиль и формы напрямую вызывают API; после изменений нет общего механизма обновления каталога и карточки фильма.
7. Общие компоненты знают маршрут каталога. Например, PageState одновременно отображает состояние и выбирает переход.
8. Нет автоматических проверок, защищающих восстановление сессии, повтор запроса после 401 и состояние URL.

## Целевая структура

```text
src/
  app/
    providers/           # QueryClientProvider, Ant Design, восстановление сессии
    router/              # таблица маршрутов и защита профиля
    api/                 # подключение обработки истёкшей сессии
    styles/              # глобальные стили и тема Ant Design
    App.tsx
  pages/
    movies/
    movie/
    login/
    registration/
    profile/
    not-found/
  widgets/
    header/              # логотип, поиск и ссылка профиля
    footer/
  features/
    auth/                # вход, регистрация, выход
    search-movies/       # поле, debounce и подсказки
    edit-profile/
    manage-movie/        # добавление, изменение и удаление
  entities/
    movie/
      api/               # HTTP-функции, query keys/options
      model/             # типы фильма и DTO
      lib/               # параметры каталога и преобразования данных
      ui/                # карточка, постер, скелетон
      index.ts
    user/
      api/               # current user и обновление пользователя
      model/             # типы, преобразование ролей, session store
      index.ts
  shared/
    api/                 # Axios и разбор ошибок; без импорта store
    config/              # runtime API URL и константы маршрутов
    lib/                 # cookie, технические helpers
    ui/                  # Logo, Loader, презентационный PageState
  index.tsx
```

Это ориентир владения кодом, а не требование заранее создать все каталоги. Hero сначала остаётся в pages/movies: сейчас он нужен одной странице. MoviesList также остаётся там до появления второго реального потребителя. В manage-movie формы лежат рядом с общей логикой преобразования значений, без объединения их в одну сложную форму.

## Правила зависимостей

- Направление импортов: app → pages → widgets → features → entities → shared. Любой слой может пропускать промежуточные слои.
- Срезы одного слоя не импортируют друг друга. Их взаимодействие собирает вышестоящий слой.
- Внешние потребители используют публичный index.ts конкретного среза; внутри него — относительные импорты.
- Не делать общий index.ts, экспортирующий весь слой, и не импортировать собственный публичный API изнутри среза.
- MovieCard не импортирует manage-movie. Страница передаёт готовые действия через props/slot.
- PageState получает текст и действие через props. Тексты 404 и переход в каталог принадлежат странице.
- Чтение параметров каталога остаётся рядом с movie, поскольку используется каталогом, карточками и поиском. Оно не попадает в shared под видом общего URL-helper с зависимостью от MovieType.
- shared/api не знает о Zustand, QueryClient или сущностях. Обработчик завершения сессии подключается в app после создания QueryClient и до первых запросов.
- Алиасы новых слоёв синхронно добавляются в Vite и TypeScript. Старые удаляются только после миграции всех потребителей.

## Где хранится состояние

| Данные | Владелец |
| --- | --- |
| Список фильмов, totalResults, загрузка и ошибка | TanStack Query, ключ с нормализованными type/q/page/size |
| Открытый фильм | TanStack Query, отдельный ключ фильма |
| Подсказки поиска | TanStack Query, отдельный ключ нормализованного запроса |
| Текущий пользователь и вычисляемые права | TanStack Query, current-user query; роли преобразуются на границе API |
| Фаза сессии и её поколение при смене аккаунта | Маленький Zustand store в entities/user |
| Токен | Существующая cookie; без дополнительной копии в Zustand/localStorage |
| Применённые параметры каталога | URL |
| Ещё не отправленный текст поиска | Локальное состояние search-movies |
| Значения форм и ошибки полей | Ant Design Form |
| Открытая форма, выбранный для изменения фильм | Локальное состояние страницы/сценария |
| Активный трейлер, ошибка картинки | Локальное состояние компонента |

Не копировать данные current-user query в Zustand. Не заводить общий isFetching или общий error для независимых запросов. Подписываться на конкретные поля Zustand через селекторы.

## Критерии завершения

- Все рабочие страницы и состояния дизайна сохранены.
- В приложении нет Redux и дублирования кеша API в Zustand.
- Нет зависимостей shared от app/entities/features и импортов между соседними срезами.
- URL остаётся единственным источником применённых параметров каталога.
- Восстановление сессии, выход, 401 и параллельные запросы покрыты проверками.
- После мутаций каталог, детали, поиск и профиль показывают актуальные данные.
- Новые компоненты и стили читаемы, публичные API небольшие, отсутствуют универсальные абстракции без реальных потребителей.
- Проверки проходят после каждого этапа; функциональные изменения backend и новая авторизация вынесены в отдельные задачи.
